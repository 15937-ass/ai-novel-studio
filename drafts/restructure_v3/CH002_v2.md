# CH002《没人发送》— v2

> 状态：V3 CANDIDATE
>
> 硬推进：
> 多终端确认 → 无正常发送者 → 普通解释排除 → 三年前旧路径 → 2035同类事件。
>
> 章尾钩子：单点异常升级为跨年份异常。

北连廊坍塌后的第二天，学校照常上课。

围挡换成了硬质的，工程车停在断口附近，绕路的人比平时多走七八分钟。食堂照常开门，早八照常点名，宿舍群里已经有人把“提前十五分钟封路”做成了表情包。

只有经过北连廊附近的时候，声音会少一点。

沈既明上午去实验室，路过围挡，看见工人正在量断口尺寸。公告也给出了初步方向：连续强降雨、连接位置结构损伤、排水和维护记录正在复核。

他反而希望这部分越普通越好。

桥为什么塌，可以慢慢查。

真正让人睡不好的，是那条消息。

联合实验室里摆了七台借来的设备。学生、保洁、体育馆工作人员，还有一个当天只来学校参加讲座的校外访客。陆峥昨晚几乎没睡，把能联系到的人逐一找了一遍，确认原始记录还在以后才把设备借过来。

他没有和沈既明一项项对答案，只把结果一次讲清楚：“七台设备型号不同，彼此没有直接关系，全部在17:16前后收到同一条封路提醒。时间误差不到十秒。截图造假和你个人设备异常，基本可以先放掉。”

沈既明看着桌上那排手机。

昨天那条消息只有一台的时候，看起来像一个问题。

七台放在一起，已经不像了。

梁慎之主持核查，没有让人一开始就往“系统异常”上靠。信息中心先按最普通的路径查：值班人员临时操作、自动提醒、旧模板、缓存、设备时间错误。

每一种都有人认真去核。

因为只要其中任何一种成立，事情就可以回到一个正常的世界。

结果到中午，没有一种完全对得上。

17:31的事故通知有完整发布链。

谁提交，谁审核，谁发出，都能查。

17:16没有。

信息中心的人把页面转过来，没有念那些字段，只解释结果：“终端这边能证明消息来过，发布端找不到对应动作。不是说绝对没人发，而是按现在能查到的正式流程，没有这个发送者。”

沈既明问：“那它从哪里进来的？”

“还在往前追。”

对方调出传播路径。

正常校园通知应该从现行发布入口进入，再分发到导航、校园服务和个人终端。

17:16那条消息前面多了一段。

一条三年前就已经退出正常发布链的历史路径。

梁慎之盯着那个名字看了很久，才问它现在是否还承担任何正式功能。

答案是否定的。

它还留在系统里，但正常情况下不再负责发布消息。

陆峥把技术解释压成一句人话：“就是旧门已经封了，但昨天有人从这扇门留下了脚印。现在还不知道是谁进来的。”

这比“旧门铃”更让沈既明不舒服。

门铃只是响。

脚印意味着真的经过。

三年前为什么停？

因为2034年栖州城市系统做过一次较大迁移，学校部分旧接口一起退出。

这条线追到这里，本来应该暂时停住。

程见微还没加入。

宋亦衡也只是临时被叫来帮忙核对几份设备记录。

但梁慎之没有让大家散。

他让人把历史索引往前拉。

不是因为已经认定三年前发生过什么，而是因为如果一个停用入口现在重新出现在路径里，就必须先知道它过去和什么东西连过。

旧记录很多。

大部分毫无意义。

直到下午两点四十，一条2035年的城市交通复盘被筛出来。

地点：

**南淞路下穿通道。**

当天暴雨。

排水设备故障。

正式交通调整命令下发前，导航系统已经开始建议车辆绕行。

提前：

**十九分钟。**

房间里没人立刻说话。

北连廊，十五分钟。

南淞路，十九分钟。

两件事相隔两年，系统不同，地点不同。

沈既明没有说“同一个问题”。

这次他忍住了。

梁慎之也没有替任何人下结论，只让人把2035那份记录完整调出来。

记录最后有一句很轻的复盘备注：

**提前响应来源未完全确认，因处置结果有效，不再单列追踪。**

沈既明看着那一行。

昨天以前，他以为自己追的是一条没有发送者的消息。

现在他第一次意识到——

这座城市可能早就发生过类似的事。

而上一次，因为它做对了，没人继续问。
