# Volume 1 Pacing v2 — 信息推进与章节密度

> 状态：ACTIVE CANDIDATE
>
> Director反馈：
> “对于一个线索的追踪推进过于慢，读几章没有推进就像水文一样。”

## 1. 新章法

每章必须至少完成：

**A. 一个硬推进**
以下至少一项：
- 新事实；
- 排除一个主要解释；
- 权限/资源实质变化；
- 角色立场不可逆变化；
- 事件造成现实后果；
- 新问题替换旧问题。

并且：

**B. 一个软推进**
以下至少一项：
- 关系变化；
- 人物缺陷暴露；
- 城市/制度现实扩展；
- 情感债务；
- 伏笔推进。

只有“继续查、再确认、又发现一份材料”的章节不成立。

## 2. 连续两章规则

连续两章不得只有同一类型动作。

禁止：
- 查记录 → 查更多记录
- 问人 → 再问另一个人
- 找权限 → 再找权限
- 发现异常 → 发现相似异常

必须交替：
> 查到东西 → 现实验证 / 做出决定 / 产生后果 / 关系改变

## 3. 线索寿命

小线索：
- 1章内回收或升级。

中线索：
- 2–3章必须发生一次性质变化。

核心谜团：
- 可以长，但每3章必须改写读者对它的理解。

## 4. 每章结束标准

不能只用：
> “还有更早记录。”
> “文件缺了。”
> “有人知道。”
> “继续调查。”

章末最好让问题发生变化。

例如：

旧问题：
> 谁发了通知？

新问题：
> 没人发，但多人都收到。

再下一次：
> 消息经过一个三年前停用的入口。

这才叫推进。

## 5. 场景压缩

如果两个连续场景的功能分别是：
- 获取信息A；
- 获取信息B；

且没有明显情绪/关系/现实后果变化，优先合并。

一章默认3–5个有效场景。
不是每一个调查步骤都值得独立成章。

## 6. 第一卷规模重新评估

此前工作目标100–120章属于过细拆分。

按当前Style与推进密度，建议工作目标改为：

> **70–90章 / 35–45万字**

单章平均更完整，减少“一个线索拆五章”。

最终章数仍可根据实际正文调整，不机械追数字。

## 7. 前15章重构结论

当前CH001–015信息密度偏低。

建议重切为约8章：

1. 北连廊事故 + 提前15分钟
2. 多终端收到 + 无发送者 + 三年前旧入口
3. 程见微进入 + 2035相似事件 + 宋亦衡进入
4. 南淞路现实验证 + 多条候选 + 企业“长期行为漂移”
5. 乔映真进入 + 权限边界 + 缺失摘要 + 新异常指向死人回访
6. 死人来电 + 进入老楼 + 现实问题仍在
7. 已结案≠已解决 + 跨版本持续关联
8. 资源优先 + 未完成公共责任原则 + “谁决定什么时候完成？”

这是结构压缩，不等于删掉生活感。
恰恰相反：
生活细节保留，但不再让一个信息点独占一章。
